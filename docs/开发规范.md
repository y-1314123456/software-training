# 小组开发规范

## 1. 代码风格

1. Java 采用小驼峰命名，包名全部小写；类名大驼峰。
2. vue 组件文件名大驼峰，变量小驼峰。
3. 数据库表名下划线命名。

## 2. Git分支策略

1. main 分支：保存稳定可运行版本，禁止直接在 main 开发。
2. 开发新建 feature 分支，命名格式 `feature/模块名`

> 示例：feature/ai-generate，feature/agent-chat

## 3. Commit提交注释规范

格式：`类型:简短描述`

- feat: 新增功能
- fix: 修复bug
- docs: 修改文档
- refactor: 代码重构

示例：

`feat:实现AI图片生成商品信息`

`docs:完善docs文档骨架`

## 4. PR合并流程

1. 在 feature 分支开发完成。
2. 提交 Pull Request。
3. 组员简单评审，确认无误合并入 main 分支。
4. 合并完成后删除本地 feature 分支。

## 5. 项目命名约定

1. 后端 controller/service/mapper 按照模块划分。
2. DTO 区分 request 入参、response 出参。
3. AI相关配置统一放置在 config 包。
4. sql 脚本改动统一更新到 docs/sql/init.sql，不随意本地修改数据库。
